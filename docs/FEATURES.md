# NetMate 功能说明

适用范围：Windows、macOS、Linux 桌面端及 Android。iOS 另行规划。

## 配置和账号

在“配置设置/设置”的账号或 WiFi 卡片点击“编辑”。账号支持用户名、服务器、运营商与密码；WiFi 支持 SSID、密码、优先级、认证要求、每网络自动连接及关联账号的上下顺序。保存保留原 ID，账号关联不会因为修改密码而丢失。密码留空保留原密码，WiFi 的“清除 WiFi 密码”才会明确清空。

清除应用内 WiFi 密码后仍保留网络安全类型，Windows 可继续使用已保存的系统 profile；首次连接安全网络需要填写密码。

附近 WiFi 卡片点击“扫描附近 WiFi”刷新，显示信号、安全类型和已保存标记。选择未保存网络会预填新增表单；已保存网络直接进入编辑。权限拒绝、定位关闭、扫描超时或系统限流均会显示重试说明，空结果仍可手动填写。

配置通过串行队列保存，revision 递增。桌面显示保存和生效状态；Android 显示保存及同步阶段，原生层拒绝旧 revision，失败后提供重试入口。

Android 保存密码时先写独立批次的安全条目，再提交配置；保存失败保留原配置和原密码。读取或校验失败显示错误，可手动重试，不自动覆盖已有配置。旧明文及旧安全引用在下次成功保存时迁移；已经丢失的密码需要重新录入。历史日志读取失败不会阻止核心服务加载。

桌面开机自启设置等待操作系统结果。系统拒绝更改时显示原因，并把自启开关恢复为系统实际值，本次保存的其他设置保留。

## 登录、注销和网络状态

手动登录、托盘登录和自动认证都按当前 WiFi 的有效关联账号顺序尝试；没有有效关联时使用当前账号。一个账号异常或超时后继续下一个。校园网、移动、联通、电信四种选项使用一致的协议样例。

点击“断开连接”会先持久暂停自动认证，再串行注销。注销失败也保持暂停，退出应用或重启后仍保留；“恢复自动认证”或再次手动登录可解除。WiFi 系统关联规则独立于认证暂停。

两端首页区分 WiFi 已关联、门户认证和互联网可达。门户返回成功但互联网不可达时保留认证状态，显示联网确认进度；未保存 WiFi 规则的校园网也可登录、注销或恢复认证，没有有效账号时提供添加入口。Android 前台与后台共用原生串行认证引擎，门户及联网探测绑定实际 WiFi Network。注销优先使用匹配当前网络身份的成功会话；没有匹配会话时只接受当前有效账号的唯一门户，无法确定时提示先登录确认。

桌面认证前刷新网络快照，使用当前 WiFi 接口的地址；尚未获得 IPv4 时等待地址就绪，不借用 VPN 等其他接口。成功认证的门户与网络身份独立保存，重建服务后可向原会话门户注销。旧版没有记录且当前规则对应多个门户时，会提示重新登录后注销。窗口隐藏并销毁后，网络事件仍处理认证和取消；重建窗口显示最新状态，托盘与窗口共用状态发布入口。

## 连接与重连

WiFi 卡片提供自动连接开关和手动连接；只有一个已保存配置或当前断网时，仍可手动连接。编辑安全类型时留空可清除原限定，连接时再按扫描结果和密码确定安全方式。

“启动时自动连接”控制启动选择，“断线自动重连”控制后续故障恢复。只开启启动连接时执行一轮，失败后停止自动轮询。启动时开启“保持当前连接”会先确认当前网络；关闭时从附近优先级最高的候选开始，包括当前已经连接已保存网络的场景。保持当前连接不阻止后续故障切换。

心跳、网络事件和启动事件进入统一恢复编排。运行中先确认当前网络，再按优先级数字从小到大尝试其他开启自动连接的规则；同优先级保持配置顺序，同名规则以配置 ID、安全类型及可选 BSSID 区分。某个 WiFi 关闭自动连接不会阻止其他已开启候选的恢复。

“每个 WiFi 最多尝试次数”包含首次尝试，范围 1–10，默认 3；历史 0 值显示并按 1 执行。每次关联或认证失败消耗一次尝试，账号按关联顺序执行。门户认证成功后不重复提交认证，按心跳间隔确认互联网，连续失败达到阈值才切换下一候选；普通热点同样需要通过联网确认。次数和冷却参数独立于心跳开关，始终可以配置。

全部失败后显示失败原因、下次重试时间和“立即重试”；运行中沿用配置冷却，冷却为零仍至少等待 5 秒。手动连接立即使旧任务失效，物理连接命令串行执行；关闭自动重连、关闭系统 WiFi 或停止服务会发布终止状态。主动注销暂停自动认证，不以换网绕过暂停。

Android 按本轮候选提交应用自己的网络建议，撤销失败目标，成功后保留成功目标。提交建议仅表示开始等待，应用须确认实际目标 SSID、安全类型、可选固定 BSSID、IPv4 和互联网可达后才报告恢复。系统未切换时显示等待或超时，并提供系统 WiFi 设置入口。WPA2/WPA3 过渡模式接受实际协商结果；最终接入点由系统选择。[Android 官方网络建议说明](https://developer.android.com/develop/connectivity/wifi/wifi-suggest)

Android Enterprise/WEP 网络通过系统 WiFi 设置连接，应用内自动连接开关禁用，手动“连接”打开系统设置。已有规则会关闭应用内自动连接，认证要求、关联账号及优先级保留；这类规则可以与开放/个人密码网络同时保存，不会阻断整份后台配置同步。

Android 13+ 的“附近 WiFi 设备”权限可在首次引导及“权限状态”中申请，手动连接前也会检查；拒绝后提供授权重试说明。Android 12+ 联合申请粗略/精确定位，WiFi 扫描仍以精确定位的实际授权结果为准。依据：[WiFi 权限](https://developer.android.com/develop/connectivity/wifi/wifi-permissions)、[定位运行时权限](https://developer.android.com/develop/sensors-and-location/location/permissions/runtime)。

Windows 支持首次连接开放和个人密码网络，profile 仅写入当前系统用户。企业认证沿用系统配置。macOS 网络字段由 Darwin 原生结构解析，字段缺失/非法时逐项回退。

## 日志与更新

两端日志查询、筛选和导出使用同一持久历史来源，保留最近 7 天，单文件上限 5 MB，最多 3 个历史文件。桌面保存结构化 JSONL，并原位读取旧文本日志；Android 前台、后台和 JS 记录统一保存。当前尚未落盘的记录按条目 ID 合并。超过页面加载数或跨重启的记录仍可查询、筛选和导出。

日志页沿用浅蓝/深蓝主题，支持中文级别、关键词、来源、时间范围、加载历史和刷新。列表展示摘要，详情完整显示消息及结构化数据并可复制已脱敏内容。查看历史时提示新记录数量，不强制跳回顶部；窗口显示或 Android 返回前台会补取遗漏记录。默认导出全部保留日志，也可导出当前筛选；文本 LOG 和 JSON 均包含系统、应用信息。清空同时作用于持久记录及页面，并按代次处理并发写入。读写、清空和导出失败会显示错误并保留已有可读内容。

桌面文件日志不可写或单条记录超过文件大小上限时，停止本次文件写入并报告错误，内存记录仍可查看。桌面关闭自动更新会取消待执行检查，重新开启后安排一次 30 秒后的检查，手动检查独立执行。更新下载失败后重新下载会清除旧错误，按新进度展示下载完成与安装入口。

Android 设置页“应用更新”支持手动检查、应用内进度、取消/重试，重启后恢复下载状态。下载完成校验包名、版本和签名，通过后提供安装入口；缺少安装权限时引导到系统授权页，返回后继续安装。系统安装确认由用户操作。

Android 9 的 APK 读取同时请求新旧证书标记，确保系统实际采集证书；签名校验继续使用当前证书和轮换历史，证书缺失或多签不匹配均拒绝安装。依据：[Android 9 PackageManager 实现](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-9.0.0_r47/core/java/android/content/pm/PackageManager.java)。

通用包 versionCode 为基础版本码 × 10，ABI 分包额外加 1–4。发布时递增基础版本码，下版通用包版本码大于上一版所有 ABI 分包。测试 APK 使用独立应用 ID 和测试签名，不用于正式分发。

## 验证范围

自动测试使用模拟账号、受控门户和无线硬件边界，验证实际 UI、IPC/原生桥接、调度和存储。真实校园网可达性、运营商开通情况、厂商后台保活及实际无线驱动行为需要对应设备和环境验证，测试通过不代表这些外部条件已验收。
